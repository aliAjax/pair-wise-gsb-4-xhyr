# License Lens · 合规裁决台

纯前端开源依赖许可证合规分析工具（无后端，台账存储于浏览器 localStorage）。在原有「粘贴/上传依赖清单 → 识别许可证 → 查看依据 → 导出报告」的基础上，改造为**可追溯的合规裁决台**。

## 可追溯模型

- **检查批次（Inventory）**：每次检查保存检查时间、项目分发方式、裁决规则版本，以及该批次的逐项结论快照。
- **逐项裁决（Verdict，只追加）**：同一依赖在新批次 / 新规则下重检时**只生成新裁决**；历史结论、许可证依据、人工覆盖原因全部不可变保留，不覆盖、不删除。
- **时间线核对**：每个依赖可展开完整裁决时间线（系统自动裁决 / 人工覆盖、规则版本、当时分发方式、依据、覆盖原因），页面刷新后仍可逐批核对。
- **人工覆盖留痕**：覆盖结论必须填写原因，生成一条新的「人工覆盖」裁决并记录覆盖人；系统原结论与依据原样保留。
- **导出**：支持当前批次 Markdown 报告（含逐项依据/覆盖原因）与完整台账 JSON（可再导入）。

## 分发方式绑定（硬规则）

GPL / AGPL / LGPL / Proprietary 等结论按批次选择的**项目分发方式**分别裁决：

| 分发方式 | GPL-3.0 | AGPL-3.0 | Proprietary |
|---|---|---|---|
| 二进制公开分发 | 高风险 | 高风险 | 高风险 |
| SaaS 对外服务 | 需复核（GPL 不分发；AGPL 仍高风险） | 高风险 | 需复核 |
| SaaS 内部分发 | **高风险（禁止自动降为通过）** | **高风险（禁止自动降为通过）** | **需复核（禁止自动降为通过）** |

选择「SaaS 内部分发」时，受保护许可证的高风险标记**不能被自动降为「兼容通过」**：界面以 🔒 标识并给出依据；人工若强行覆盖为通过，必须填写授权/隔离方案等依据，覆盖动作永久留痕并自担合规责任。

## 使用

直接打开 `index.html`，或：

```bash
npm run dev      # 本地开发
npm run build    # 生产构建
```

输入支持每行 `名称@版本 许可证`（支持 scoped 包名、SPDX 别名如 GPLv3），也可直接粘贴 `package.json` / `package-lock.json`，或拖放文件。未识别许可证一律标记为「需复核」。首次打开会载入含两个历史批次和一条人工覆盖记录的示例台账。
